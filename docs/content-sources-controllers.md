Primary references consulted on **2026-10-22**. Baseline: Kubernetes **1.35.0**, kind **0.31.0**, BusyBox **1.37.0**. ## Shared implementation and validation

`lab/level-4/custom-controllers/greeting-operator` is maintained once for the three implementation chapters. `lab/level-4/crds/greetings.yaml` is generated from its typed API with controller-gen; it is the same resource definition taught in `crds`, not an unrelated duplicate. Generated deepcopy code, go.mod and go.sum are checked in. A Dockerfile and namespaced manager/RBAC fixtures make the optional runtime path complete.

Actual authoring checks:

- Official Go **1.25.14** supplied in a temporary toolchain directory was used; the system Go/PATH was not changed. `GOTOOLCHAIN=local`, `GOMAXPROCS=2`, `go test -p 2` and temporary caches/module paths constrained the build.
- Module dependencies were downloaded through the standard Go module mechanism after sandbox network authorization. controller-gen **0.20.0** actually generated deepcopy and CRD artifacts. The generated CRD includes both maximum-name length and DNS-1035 CEL rules.
- `go test -p 2 ./...`: passed, covering ten top-level unit tests, including two invalid-name subcases. No manager or API server was started. A direct client write-call spy supplements resourceVersion-based observations because fake metadata behavior is not a real API guarantee.
- `go build -o /private/tmp/k8s-greeting-controller ./cmd`: passed. The executable was built but never launched. No Docker image was built and no image/runtime compatibility is claimed.
- All six chapter modules imported with the raw fixture loader; 33 authored Bash blocks passed `bash -n` and all quiz indexes were valid (three questions per chapter).
- Targeted ESLint and TypeScript for the six chapter modules: passed at this integration state. Prettier was limited to owned non-generated files; Go files were formatted with the matching Go toolchain.
- `bun run check:labs`: passed at this integration state, parsing 91 YAML files / 145 documents, two JSON files, eight shell scripts and twelve Python files. These global counts can change as other chapters are integrated; they are a dated static snapshot, not cluster execution evidence.

No real Kubernetes exercise, CRD installation/deletion, controller process, leader election, port-forward, Docker build, envtest service, cluster creation/deletion, commit or push was performed. Runtime observations in lessons are expectations for a learner's independently chosen disposable lab. Application tests and browser evidence are tracked by the integrating agent.
