## Official references reconsulted

Opened on **2026-10-23** for this pass; the existing [source index](content-sources.md) retains the other chapter-specific references and version/dependency ledgers. This review does not claim that every upstream page was newly checked.

- [Kubernetes 1.35 resource management](https://v1-35.docs.kubernetes.io/docs/concepts/configuration/manage-resources-containers/): requests drive scheduling; CPU throttling and reactive memory enforcement have distinct contracts.
- [Kubernetes 1.35 Deployments](https://v1-35.docs.kubernetes.io/docs/concepts/workloads/controllers/deployment/): controller convergence, availability and stalled progress are distinct from API/CLI completion.
- [Kubernetes 1.35 kubectl wait](https://v1-35.docs.kubernetes.io/docs/reference/kubectl/generated/kubectl_wait/): explicit condition waiting and bounded timeouts; syntax checks do not establish readiness.
- [Kubernetes 1.35 Service proxies](https://v1-35.docs.kubernetes.io/docs/reference/networking/virtual-ips/): configured iptables, nftables and IPVS modes; a Service virtual IP is not itself an ordinary container listener.
- [kind 0.31.0 release](https://github.com/kubernetes-sigs/kind/releases/tag/v0.31.0), [its actual release assets](https://github.com/kubernetes-sigs/kind/releases/expanded_assets/v0.31.0) and [versioned quick start](https://raw.githubusercontent.com/kubernetes-sigs/kind/v0.31.0/site/content/docs/user/quick-start.md): matching binary/checksum filenames, node-image baseline, kubeconfig path selection and explicit target names. Actual binary downloads/installation were not performed.
- [Kubernetes 1.35 kubectl Linux installation](https://v1-35.docs.kubernetes.io/docs/tasks/tools/install-kubectl-linux/): architecture-specific binary/checksum pair and verification before installation.
- [curl manual](https://curl.se/docs/manpage.html#--retry-connrefused): bounded retries for connection refusal, without disabling HTTP failure handling or TLS validation.
- [Moby 28.5.1 kill implementation](https://raw.githubusercontent.com/moby/moby/v28.5.1/daemon/kill.go): the manual-stop marker confirms the existing lesson's distinction between daemon-mediated kill and an application process exit. No Docker operation was executed to inspect it.

One attempted refresh of the versioned Pod lifecycle page timed out. The memory-enforcement correction was verified against the successfully retrieved versioned resource-management reference above; that timeout is not treated as a successful source check.
