## Confirmed corrections

1. **Temporary-file collisions:** API saved object, platform render and Go build commands previously targeted fixed `/tmp` filenames. They now create private directories, preserve the shell variable required by subsequent steps and describe removal of that exact directory. The two fixture READMEs mirror the commands.
2. **New Greeting rollout verification:** a successful Deployment rollout command could describe the old child before reconciliation of a new Greeting input. Custom-controller and Operator corrections now capture the generation returned by the patch, wait for that exact `status.observedGeneration`, then wait for Ready and inspect the child/HTTP result. This is not a claim that observedGeneration alone means completed work.
3. **Large source block:** the custom-controller course now displays the real Reconcile, ownership and status functions separately, with source paths and an explicit explanation that the complete program remains in the shared project. No pseudo implementation replaces runnable files.
4. **CRD challenge path:** `spec.properties` was ambiguous at CRD root. The correction identifies `spec.versions[].schema.openAPIV3Schema.properties.spec.properties` for v1alpha1 and its own required list.
5. **CSI JSONPath verification:** the actual displayed template reads the restored claim and prints a newline when evaluated by the pinned client-go parser. Comparing the final source with the parent’s pre-review snapshot shows no net source difference; this is validation evidence, not an additional correction.
6. **etcd cleanup ownership:** a refused preflight must not authorize deleting a pre-existing named container/volume. The recovery script records its explicit Docker context and random run ID in a private local file after collision checks and labels objects it creates. `cleanup.sh` requires that exact marker; `ownership.py` validates every present candidate before deletion and refuses foreign labels. Container removal uses immutable IDs. No deletion runs automatically on error; partial failures retain their marker. Docker volume deletion remains name-based, so the lesson explicitly excludes concurrent administrative changes during cleanup.

### ConversionReview status discrepancy

The official [CRD versioning guide](https://kubernetes.io/docs/tasks/extend-kubernetes/custom-resources/custom-resource-definition-versioning/) currently illustrates failed conversion with `result.status: Failed`. The pinned [metav1 v0.35.0 Status type](https://github.com/kubernetes/apimachinery/blob/v0.35.0/pkg/apis/meta/v1/types.go) documents `Success`/`Failure` and defines `StatusFailure = "Failure"`. The pinned [conversion implementation](https://github.com/kubernetes/apiextensions-apiserver/blob/v0.35.0/pkg/apiserver/conversion/webhook_converter.go) accepts only `StatusSuccess`; its [upstream tests](https://github.com/kubernetes/apiextensions-apiserver/blob/v0.35.0/pkg/apiserver/conversion/webhook_converter_test.go) use `StatusFailure` for error responses. These files were inspected from the already downloaded versioned Go module cache; the metav1 source was also fetched live.

The fixture and its tests now use `Failure` to match the canonical Status contract. The previous `Failed` value was already treated as an error by that converter: this is a contract normalization, not a claim that the old code incorrectly reported conversion success.
