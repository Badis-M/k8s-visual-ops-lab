## Validation boundary

Chapter output descriptions are expected observations, not captured Kubernetes results. The restore script rejects integrity failure before its first kubectl call and refuses overwriting an existing target file. The local archive directory remains on the same host as kind, so the drill cannot prove survival of host loss. Backup data is synthetic; real backups require encryption, independent storage, restricted access/deletion and tested recovery keys.

## Local static and isolated script checks

- Targeted ESLint on the four chapter TypeScript files: passed.
- `bun x --no-install tsc --noEmit`: passed at this batch's integration state.
- All four modules loaded with a raw YAML/shell loader. `zsh -n` parsed the authored chapter shell snippets; the strategic JSON patch parsed successfully.
- `js-yaml` parsed eight YAML files containing 15 documents.
- Bash/POSIX-shell syntax checks passed for all four backup scripts.
- A temporary local transport stand-in replaced kubectl only for an offline script test. It mapped the two namespaces to separate temporary directories and executed the file/archive commands locally. Capture, original checksum, isolated restore, application count/total checks, exclusion of the later write, populated-target refusal and repeated-seed refusal all passed.
- A deliberately corrupted copy failed archive integrity before the transport stand-in was invoked. The original archive and source dataset remained intact.

The transport test establishes script/archive behavior only. It does not test a Kubernetes API, admission policy, actual storage permissions, volume binding, image pull, network or runtime security profile. All real cluster exercises remain unexecuted. Application integration/browser results are owned by the integrating agent in `docs/content-implementation.md`.
